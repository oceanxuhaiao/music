# 一起听 · 网易云音乐

**把一个人的歌单，变成你和 Coo 的共同话题。**

工作时随手放歌、深夜循环收藏，或突然切到一首老歌——「一起听」让桌宠在曲目切换后，参考网易云评论区里的感受，用它自己的语气陪你聊一两句。你继续听歌，它偶尔接上一句，陪伴不用每次都由你开场。

- **评论区里找话题**：参考少量热门与最新评论，用自己的话回应，不逐条播报。
- **热闹还是安静，你来选**：主动评论间隔可调，最大字数可设置，也能一键关闭陪听评论。
- **随你切歌，不追着补评**：合并连续快切，丢弃过期请求；播放器未打开时安静等待，网络异常时回退普通陪听。
- **还是你熟悉的那个 Coo**：沿用现有人格、模型和气泡发言，不增加一套模型或 TTS。

Windows 专用的非官方 Cortico World 扩展，与网易云音乐及 Coopanion 官方无隶属关系。读取的是曲目信息和评论摘录，**不是音频**；不需要网易云登录 Cookie。模型请求仍按你已有服务计费。字数上限由模型遵循，不是强制截断；窗口标题模式无法精确判断暂停和发行版本。

0.3.0 补充了未启动播放器、快切与来回切歌、拖动进度、暂停恢复、网络限流、读取器卡死及反复启停的防护。World 页可查看当前曲目与运行状态；详细行为及能力边界见 [复杂场景说明](docs/RESILIENCE.md)。

0.3.1 在配置页增加「评论最大字数」（默认 80，范围 10–500，含标点和外语字符）；「主动评论最短间隔」为 30–3600 秒，默认 120。两项热更新。间隔由扩展代码控制请求频率，字数通过当前状态工具和环境提示词传给模型遵循；公共 World 接口不拦截其他 World 的 pet_say，因此字数不是输出层强制截断，也不影响普通聊天。

顶部五项是状态标签，不是会自动亮起的灯：读取状态、当前曲目、陪听开关、最近一次评论区获取状态、本次运行成功入队的评论请求次数。请求次数不等于已展示气泡次数，重启清零。宿主在开页或显式刷新时取这些标签，不保证实时刷新；显示旧信息时刷新页面。配置中的开启复选框是设置项，不代表播放器正在运行。

0.2.0 新增评论区参考：默认在评论机会到来时检索对应歌曲，并获取最多 3 条热门、2 条最新评论的短摘录（每条最多 240 字），一同交给桌宠。桌宠参考网友感受，用自己的话回应，不逐条朗读。可在 World 配置页关闭「参考网易云评论区（联网）」。

匹配核对歌名、歌手及可用的专辑字段；窗口标题只在能与检索结果的「歌名 - 歌手」或反向格式相符时采用。缺少歌曲 ID/专辑时按检索排名选择匹配项，并标为 `title-artist-version-unverified`，不保证与当前录音的发行版本完全一致；不同版本的评论区可能不同。匹配失败、接口限流或超时就退回普通陪听，不编造网友观点。成功结果缓存 30 分钟，失败缓存 5 分钟，最多缓存 40 首。

## 安装

需要 Windows 10 1809+ / Windows 11、网易云音乐桌面客户端，以及支持 **World API 6** 的 Coopanion / Cortico。开发检查使用 Cortico 0.2.5；不能仅凭 Coopanion 的版本号判断接口兼容性。

扩展 0.3.2 已针对 **Coopanion 0.2.6** 校验：其随附 Cortico 为 0.2.5，World API 仍为 6。新版「输入气泡」开关仅影响用户输入气泡，音乐评论仍使用桌宠 `pet_say` 输出。已有音乐配置、World ID 和工具名均保持兼容，不需重装或重建配置。

在 Coopanion 高级模式 → 扩展 → World 搜索 `cortico-world-netease-companion` 安装，然后重启进程，在 World 总览启用「一起听 · 网易云音乐」。若搜索尚未收录，可在手动安装中输入完整包名。当前发布状态请以 npm registry 实际结果为准。

以下为源码本机安装方式：

1. 在本目录运行 `npm ci`，再运行 `npm run check`。
2. 打开 Coopanion 设置，进入高级模式 → 扩展 → World，选择「本机目录」。
3. 选择本项目所在目录（含 `package.json`）。若宿主拒绝中文路径，将源码放在英文路径目录后重试。
4. 安装后点击「重启进程」，在 World 总览启用「一起听 · 网易云音乐」。
5. 播放网易云音乐，切换一首歌，等待至少 8 秒。首次触发陪听，后续触发至少间隔 120 秒；扩展要求桌宠检查当前曲目、参考评论并调用 pet_say 展示简短气泡。模型响应和展示有额外延迟。

若安装器提示 API 不兼容，请先升级宿主或使用匹配宿主契约的扩展版本，不要直接把 manifest 的 api 改小。

`npm run diagnose` 会读取并输出约 10 秒的曲目信息，然后关闭读取进程，可以在安装前独立检查。它不会切歌或控制播放器。

## 工作方式

```text
网易云音乐 → Windows SMTC / 网易云窗口标题 → 曲目稳定、去重和节流
           → World 外部事件 → 原有 Cormini 人格 → 桌宠原有发言渠道
```

- 默认每 2 秒读取一次；曲目稳定 8 秒后才提供评论机会。
- 快速连切会合并，只关注当前最后一首；同一曲目不会反复触发。
- 在评论冷却期间继续更新状态；冷却结束后以当前曲目为准。
- SMTC 明确报告暂停时不触发评论，恢复播放后重新等待稳定时间。
- 可对桌宠说「先安静陪我听歌」「恢复切歌评论」，由 `music_set_commentary` 保存开关。也能在 World 配置中修改。
- 不添加第二套模型调用、不提供 TTS。事件唤醒现有模型仍会消耗其 token；两分钟间隔是机会间隔，不是保证的发言间隔。

## 能力边界

本扩展读取的是**曲目信息，不是音频**。不会将歌名当成实际听到了旋律、歌词或情绪的证据。不会修改 Persona、情绪、Memory 或 Coopanion 源码。

SMTC 可提供歌名、歌手、专辑和播放状态，但取决于网易云版本是否向 Windows 注册媒体会话。没有可用会话时默认降级为读取 `cloudmusic` 进程的非空窗口标题。降级通道把整个窗口标题当作原始曲目标签，不猜测分隔符含义，播放状态标为 `unknown`：**不能可靠感知暂停、单曲循环、相同标题的不同录音，也可能受客户端窗口标题格式变化影响**。

如果只希望在确定正在播放时评论，请在 World 配置中关闭「窗口标题降级」。没有媒体会话时将保持安静。切歌到评论之间存在采样、模型响应和桌宠展示延迟，不会卡住播放器来制造静音间隙。

近期曲目只在扩展进程内保留最近 20 条，重启清空；进入 Cortico 的事件和工具回执按宿主原本的日志策略保存。曲目信息及评论摘录会随模型请求发送到你配置的模型服务。启用评论参考后，歌名、歌手也会发送到 music.163.com 检索。本扩展不读取账号 Cookie、不上传音频；评论读取使用网易云网站未公开承诺稳定性的接口，并非网易云官方开放平台服务，未来可能失效。只保留评论文本、点赞数、热门/最新分类，不收集评论者昵称或主页。

## 配置

World 配置页提供热更新开关和节奏设置。对应部署 `config.json` 的片段如下（合并进现有配置，不要覆盖整个文件）：

```json
{
  "worlds": {
    "netease-music": {
      "enabled": true,
      "commentary": true,
      "commentReference": true,
      "settleSeconds": 8,
      "cooldownSeconds": 120,
      "sessionPattern": "cloudmusic|netease|网易云",
      "windowFallback": true
    }
  }
}
```

`sessionPattern` 匹配 Windows 的媒体会话应用 ID，修改后重启 World。它不用于匹配歌曲内容。`windowFallback` 修改后也需重启。评论等待限制为 2–120 秒，间隔限制为 30–3600 秒。

## 更新与回退

**本机目录安装**：宿主以 link 方式加载这个目录，不从 npm 查询更新。保留目录位置，替换该目录的新版源码，运行 `npm ci`、`npm run typecheck`、`npm test`、`npm run describe`、`npm run check`，然后在 Coopanion 重启进程。配置由宿主保存在部署目录，包更新不覆盖它。

**npm 安装**：此包已发布到 npm，用户可在宿主扩展页安装包名；扩展页检查新版本、更新并重启加载。旧版本可从扩展详情选择回退，前提是其 API 契约兼容。发布者操作见 [维护说明](docs/DESIGN.md)。

使用公开 World 接口可减少宿主升级带来的影响，但不能保证未来破坏性契约变更无需适配。当前声明 `api: 6`，不兼容的宿主会由安装器拒绝。

## 开发与验证

```powershell
npm ci
npm run typecheck
npm test
npm run describe
npm run check
npm run diagnose
npm pack
```

`check` 使用 Cortico 自己的 manifest 解析器、dry-mount 和 describe 校验函数，验证构造、工具、配置归属与自描述一致性；它不启动桌宠或发送模型请求。`diagnose` 是本机音乐读取检查。完整桌宠发言效果仍需启用 World 后联调。

依据：[官方扩展安装与更新规范](https://github.com/Pal-AI-Lab/Cortico/blob/main/docs/extensions.md)、[官方 World 模板](https://github.com/Pal-AI-Lab/Cortico/tree/main/templates/extension/world)、[World 公共契约](https://github.com/Pal-AI-Lab/Cortico/blob/main/src/core/types.ts)。

0.3.4 修复未投递评论被撤回后无法重试、界面关闭陪听未清队列及读取器停止失败后重复启动的问题。曲目信息使用投递时快照；输出流程集中于可编辑的陪听指导，不再重复写入工具回执。已消费的评论机会仍去重，无法确认撤回的请求也不自动重试。配置关闭在下一次检查时处理（通常 1 秒内），不会撤回已投递的模型上下文或已经展示的气泡。

发布必须运行完整官方检查：`npm run check-official -- <已安装依赖的 Cortico checkout>`。执行 npm publish 前将环境变量 CORTICO_CHECKOUT 设为该目录；prepublishOnly 会强制执行本地验证与完整官方检查。

本次 0.3.4 也使用本机 Coopanion 0.2.8 的随附校验器通过 manifest、构造与自描述检查（World API 6）；这与真实桌宠发言验收分开记录。

## 侧栏状态灯（0.3.5）

扩展提供两颗状态灯，悬停可查看说明。音乐读取：绿色表示曲目信息新鲜（暂停也可正常读取）；黄色表示首次连接或信息过期等待恢复；红色表示读取器报错；灰色表示未运行、未打开播放器或无曲目。窗口标题模式会注明无法确认暂停。

评论区访问：黄色表示正在查询；绿色表示当前歌曲最近一次查询成功，可能来自缓存；红色表示查询失败或无法匹配，仍可普通陪听；灰色表示关闭参考、未运行、没有新鲜曲目或尚未查询。切歌后清除上一首的结果。这颗灯不代表互联网整体可用，也不代表桌宠已经发言。关闭主动陪听不会强制禁用用户主动调用评论查询工具。

状态灯由宿主轮询更新；查看状态本身不会发起音乐评论查询或唤醒模型。现有五个状态标签仍保留。
