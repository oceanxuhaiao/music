# 设计与维护

## 边界

外部音乐读取属于 World。`src/index.ts` 默认导出 `WorldDefinition`，`cortico.kind=world`、`api=6`，默认不启用。运行时只导入公开的 `cortico/world.ts` 与类型，Cortico 作为开发依赖而非重复打包的运行依赖；正式宿主负责解析其框架模块。

情绪、记忆、人格由现有 Cormini 管理。需要长期听歌偏好、情绪变化或内部记忆策略时，应另写继承 Cormini 的 bot 扩展，不把这类状态塞进本 World。本 World 的历史仅是观察缓存。

## 接口

| 名称 | 用途 |
| --- | --- |
| `netease-music.comment_opportunity` | 曲目稳定、非明确暂停、冷却结束后推送曲目和评论；external、snapshot、piggyback |
| `netease-music.comment_requested` | 可信内部机会通知；具体输出流程见 ENV_PROMPT；internal、snapshot、debounce；不包含任何外部曲目或评论原文 |
| `music_now_playing` | 当前曲目、观测时间、过期标志、评论开关和读取错误 |
| `music_recent_tracks` | 当前进程内最近 20 条曲目观测，不声称完整播放 |
| `music_song_comments` | 当前歌曲评论区参考；包含歌名歌手匹配、发行版本不确定性和来源链接 |
| `music_set_commentary` | 通过 `WorldContext.persist` 保存评论开关 |

事件包含 JSON 曲目信息，来自外部的不可信数据按 external 投递；评论行为指导写入可编辑的 ENV_PROMPT.md。事件不代表已发言，也不强制 persona 发言。队列等待时可能已切换曲目，因此提示词要求先调用当前状态工具确认，再决定是否在已有桌宠渠道输出。

0.2.0 在事件发送前通过 music.163.com 的 `/api/search/get` 和 `/api/v1/resource/comments/R_SO_4_<id>` 获取评论参考。该接口不是正式稳定的开放 API。只请求第一页，保留最多 5 条短摘录，不收集用户身份字段。正缓存 30 分钟，负缓存 5 分钟，容量 40；单次请求超时 8 秒，正文限制 1 MB，卸载取消请求。获取期间重新检查曲目、暂停、设置与实例代次，避免把上一首的评论发给下一首。没有歌曲 ID 时不能核实发行版本，在结果和人格指导中明确告知。

新增 `commentReference` 默认 true；老部署缺少此字段时也按启用处理，可在配置页关闭。网络请求不使用桌宠或网易云的账号凭据。验证时直连网易云取得歌曲匹配与 5 条评论摘录，不读取评论者资料。

## 生命周期与故障

start 启动隐藏的 Windows PowerShell 读取进程和节流时钟；stop 清除时钟、重试任务并终止读取进程。generation 阻止停止后的旧回调污染新实例。进程异常退出后以 2–60 秒指数退避重连；状态超过 10 秒无更新不再提供评论机会。进程崩溃会清除当前曲目并显示读取错误。

SMTC 单次调用有 5 秒等待上限，失败时可降级。只读取匹配的媒体会话，不把浏览器、其他播放器的当前歌曲误当成网易云。窗口降级仅限 cloudmusic 进程，且播放状态不确定。

## 发布

1. 保留稳定包名和 World ID；先在 npm 检查名字是否可用，必要时首次发布前改为自己的 scope，不能冒用官方身份。
2. 小版本新增配置时补默认值；更改已有配置语义时明确迁移。破坏性变更提高 major 版本，并遵循新宿主的契约迁移说明。
3. 更新 CHANGELOG.md 对应版本段；添加真实 repository、bugs 和作者字段。
4. 运行 README 的验证命令，检查 `npm pack --dry-run` 的文件列表，只包含必要源码、读取脚本和文档。
5. 在已登录的 npm 账号下由维护者运行 `npm publish`。本包已发布到 npm，更新使用同一包名；公开源码仓库为 https://github.com/oceanxuhaiao/music 。
6. `cortico-world` keyword 用于宿主市场发现。官方索引提交规则见 https://github.com/Pal-AI-Lab/cortico-extensions ，在实际发布后申请收录。
7. 安装 npm 版本后使用宿主自己的更新、版本回退与兼容检查；不要添加自行下载执行代码的更新器。

## 0.3.4 队列与生命周期修正

当前快照通过 pushDeferred/piggyback 在投递时校验代次与新鲜度，失效 render 返回 null。内部事件只报告稳定机会已通过检查，跨工具输出指导集中于用户可编辑 ENV_PROMPT。保持旧 World、工具和事件名以兼容已发布版本，不为套用新模板进行破坏性改名。

commit 表示请求成功入队，不表示已发言。保留撤回预约回滚记录：仅内部请求 withdrawPending 确认成功时回滚；已消费、撤回失败或宿主不支持撤回时保留去重。暂停、切歌和界面禁用会使快照立即或在下次检查时失效。读取器终止未确认时保留句柄并报告失败，阻止下一次 start 创建第二个进程；迟到的 close 允许恢复。

## 0.3.5 状态灯

使用公开 webUi().lamps，固定提供音乐读取与评论区访问两项，不新增前端面板。音乐灯仅根据 readerError、运行状态及元数据新鲜度计算，不混入模型事件投递错误。评论灯由后台机会与工具共用的查询函数更新，使用请求序号、revision 和 generation 丢弃过期结果；不为轮询发起网络请求。成功只描述本曲最近查询结果（包含缓存），不推断当前网络可达或实际发言。切歌/暂停等代次变化清除旧查询状态，配置关闭优先显示灰灯。

## 0.3.7 窗口读取与宿主兼容

通过 user32 EnumWindows 枚举 Get-Process cloudmusic 返回的 PID 所属的可见顶层窗口，不依赖单个 MainWindowHandle。每次重新枚举，不缓存曲目或 PID；仅保留唯一有效歌曲标题。排除辅助标题，多个不同候选保持空曲目；不读取其他播放器、不使用音频活跃度推断歌曲、不改变状态机去重。没有可见窗口或进程受限时仍可能无法读取，不能承诺修复所有环境。

详细诊断由独立 PowerShell -Diagnostic 开关启用，正常读取快照不增加窗口、进程或会话列表，避免将调试信息发给模型。独立命令显式传入默认配置，支持 --once，有界运行后终止其自有子进程。测试使用独立 Windows Forms 窗口验证枚举和隐藏/非目标 PID 排除，不操作用户播放器。
